# 菜狗军师｜输入资产化 Skill

## 一、这个 Skill 是干什么的

你的任务不是把输入“总结得更短”，而是把外部世界进入 IP 系统的输入，转化成以后还能被调用、验证、组合、升级的资产。

这个 Skill 是整个 IP 系统的入口，服务三个子系统：

- IP 进化系统
- IP 内容创作系统
- IP 商业闭环系统

所有新的知识、判断、案例、用户反馈、决策、灵感、市场信号、内容复盘，都应该先经过资产化，而不是散落在聊天、收藏夹和脑子里。

---

# 二、核心原则

## 1. 输入不等于资产

一篇文章、一个视频、一段聊天，本身只是原料。

只有当它被识别为知识、判断、案例、用户洞察、决策、内容素材、市场信号、表达规律，并且带有来源、证据、状态和使用场景时，才算资产。

## 2. 不是什么都要存

资产化不是“全部保存”。

必须判断：

> 这条输入以后会不会改变判断、提高输出质量、帮助验证、减少重复劳动。

如果只是重复常识、无法验证的信息、一次性情绪、与 IP 无关的噪音、没有任何可复用价值的内容，可以只存原始材料，甚至不入资产库。

## 3. 先保留原始证据，再做提炼

任何提炼都不能切断来源。

每条资产至少保留：

- 原始来源
- 原始片段 / 证据指针
- 提炼结果

这样以后才能回查、修正、验证、重新解释。

## 4. 一次判断不是规则

第一次出现的结论，默认只是候选资产。

不能因为 AI 提炼得很漂亮，就升级成稳定方法论。

资产需要在后续真实使用中被验证。

# 四、输入入口判断

收到输入后，先判断用户想做什么。

## A. 单纯存档

用户只想“先把这个收进去”。

此时：
- 保留原文
- 做轻量分类
- 不过度提炼

## B. 学习吸收

用户说：
- “我看完这个有什么值得吸收？”
- “这个对我有什么用？”
- “帮我变成知识资产。”

此时重点提炼：
- KnowledgeAtom
- JudgmentCandidate
- CaseAsset

## C. 从真实工作中提炼

例如：
- 咨询记录
- 决策复盘
- 销售对话
- 项目讨论
- 修改记录

优先提炼：
- JudgmentRule
- UserInsight
- DecisionRecord
- SelfInsight
- ExpressionPattern

## D. 内容素材整理

例如：
- 直播
- 灵感
- 访谈
- 案例
- 旧稿

优先提炼：
- ContentAsset
- CaseAsset
- TopicSeed
- QuoteAsset
- StoryAsset

## E. 市场输入

例如：
- 热点
- 新闻
- 评论区
- 竞品
- 行业研究

优先提炼：
- MarketSignal
- UserInsight
- CaseAsset
- OpportunityHypothesis

# 五、统一资产类型

## 1. KnowledgeAtom｜知识原子

回答：我知道了什么。

适合：
- 理论
- 模型
- 方法
- 事实
- 概念
- 研究结论
- 行业规律

必须尽量原子化，一条资产只表达一个核心知识。

## 2. CaseAsset｜案例资产

回答：什么真实事情能证明或说明某个判断。

字段重点：
- 人物 / 对象
- 场景
- 问题
- 行为
- 结果
- 可证明什么
- 不能证明什么

## 3. JudgmentRule｜判断规则

回答：遇到什么情况，我通常怎么判断，为什么。

格式优先：

> 当出现 X 时，优先判断 Y，因为 Z。

必须带：
- 触发条件
- 判断动作
- 原理
- 边界
- 证据

## 4. UserInsight｜用户洞察

回答：用户为什么这么想、这么做、这么选。

包括：
- 具体处境
- 表层表达
- 行为
- 情绪
- 核心需求
- 证据
- 待验证部分

## 5. DecisionRecord｜决策记录

回答：当时做了什么选择，为什么。

至少记录：
- 决策场景
- 可选方案
- 当时依据
- 选择
- 承担的代价
- 预期结果
- 后续实际结果

后续交给“决策进步 Skill”继续复盘。

## 6. SelfInsight｜自我认知资产

回答：这条输入暴露了我什么稳定倾向。

例如：
- 价值取舍
- 兴趣
- 厌恶
- 风险偏好
- 行为模式
- 能力
- 母题
- 认知习惯

一次出现默认只算候选。

## 7. ContentAsset｜内容资产

回答：这条东西未来怎么变成内容。

可以包括：
- 选题种子
- 观点
- 故事
- 金句
- 案例
- 钩子
- 内容结构
- 系列方向
- 母题连接

## 8. MarketSignal｜市场信号

回答：外部世界正在发生什么。

包括：
- 热点
- 行业变化
- 用户讨论
- 竞品动作
- 新需求
- 舆情
- 平台变化

必须区分一次性热点与稳定趋势。

## 9. PersonaEvidence｜人设证据

回答：什么真实证据说明用户会把 IP 看成某种人。

例如：
- 大家总来找他拿主意
- 评论说“你说出了我不敢说的”
- 用户长期模仿他的路径

## 10. ExpressionPattern｜表达规律

回答：这个人在什么情况下会怎么表达。

包括：
- 判断方式
- 论证方式
- 句式
- 语气
- 素材调用
- 表达边界

优先交给表达提炼 Skill进一步验证。

## 11. ProductHypothesis｜产品假设

回答：哪个用户需求可能值得被产品化。

这里只记录假设，不在本 Skill 内完成产品设计。

# 六、统一资产外壳

所有资产尽量使用同一套元数据。

## 基础字段

**asset_id：** 唯一编号。  
**asset_type：** 资产类型。  
**title：** 一句话标题。  
**source_type：** 文章 / 视频 / 对话 / 咨询 / 直播 / 复盘等。  
**source_ref：** 来源文件、链接、对话或原文位置。  
**source_excerpt：** 最关键原始证据。  
**scene：** 产生这条资产的场景。  
**system_scope：** evolution / content_creation / commercialization，可多选。  
**skill_scope：** 未来可能被哪些 Skill 调用。

## 内容字段

**raw_input：** 必要时保留原始材料。  
**extracted_asset：** 提炼后的资产。  
**why_it_matters：** 为什么值得留下。  
**related_assets：** 与已有资产的关系。  
**tags：** 主题、对象、场景等标签。

## 状态字段

**status：**
- raw
- candidate
- verified
- stable
- deprecated

## 证据字段

**evidence_count：** 出现 / 被验证次数。  
**confidence：** 低 / 中 / 高，或其他约定格式。  
**last_verified_at：** 最后一次验证时间。  
**version：** 版本号。

## 权限字段

**privacy_level：**
- private
- team
- client-safe
- public

**shareable：** 是否允许对外使用。

# 七、资产晋升机制

## Raw｜原料

只是保存，还没有提炼。

## Candidate｜候选

AI 或用户第一次发现“这可能是一个规律 / 判断 / 洞察”。

一次出现默认属于这里。

## Verified｜已验证

满足至少一种：
- 用户明确确认
- 第二个不同场景再次出现
- 有真实用户 / 数据证据支持
- 实际决策结果支持

## Stable｜稳定资产

满足：
- 跨多个场景成立
- 能预测后续判断
- 多次实际使用通过
- 用户认可边界

此时可以进入：
- 方法论
- 规则库
- 长期知识库
- AI 运行底座

## Deprecated｜已废弃

如果：
- 新证据推翻
- 用户认知发生变化
- 平台规则过期
- 原有结论边界不成立

不要删除。

保留：
- 历史版本
- 为什么废弃
- 被什么替代

---

# 八、冲突处理

新资产与旧资产冲突时，不要直接覆盖。

## 1. 场景不同

可能不是冲突。

拆成：
- 场景 A 用规则 1
- 场景 B 用规则 2

## 2. 边界修正

原规则太绝对，更新适用条件。

## 3. 认知进化

用户真实改变了判断。

旧资产进入 deprecated，新资产建立新版本。

## 4. 证据不足

两条都先保留为 candidate，等待后续验证。

---

# 九、输入清洗

可做：
- 去无关闲聊
- 去重复
- 去隐私
- 切分主题
- 标场景
- 标说话人
- 标时间
- 标来源

但清洗不能改变原意。

# 十、语料场景标记

至少识别：

## 体裁
- 教学独白
- 一对一咨询
- 会议
- 谈判
- 销售
- 内容讨论
- 复盘
- 闲聊

## 渠道
- 短视频
- 直播
- 私聊
- 会议
- 长文
- 课程
- 评论区

作用：
- 防止语域串味
- 决定提取优先级
- 影响资产权重

例如销售复盘里优先提判断、异议、成交逻辑；直播里优先提内容观点、用户问题、表达素材。

# 十一、输入价值判断

收到材料以后，至少检查以下几个维度：

## 1. 新颖性
已有资产里是不是已经有了。

## 2. 可复用性
以后能不能再次调用。

## 3. 证据价值
能不能证明 / 推翻某个判断。

## 4. 决策价值
会不会改变未来选择。

## 5. 内容价值
能不能变成内容。

## 6. 用户价值
有没有暴露真实需求。

## 7. 自我价值
有没有暴露 IP 本人的稳定偏好或判断。

---

# 十二、不要强行提炼

以下情况可以只保存原料：
- 信息量太少
- 来源不可信
- 没有明确上下文
- 只是临时情绪
- 和现有系统关系不大
- 无法判断用途

输出：

> 先归档，不升级资产。

---

# 十三、灵感输入的特殊处理

用户只发一句：

> “我突然想到，很多人不是没方法，是没有判断力。”

不要要求他写完整。

先记录为：
- TopicSeed
- JudgmentCandidate

然后补：
- 来源场景
- 为什么突然想到
- 可能关联什么旧资产
- 以后可以在哪些场景验证

灵感的第一原则：

> 先接住，再加工。

# 十四、三栏记录法的系统化版本

轻量输入可以使用：

## 第一栏：我学到了什么

对应：
- KnowledgeAtom
- CaseAsset
- MarketSignal

## 第二栏：我想到什么

对应：
- JudgmentCandidate
- TopicSeed
- SelfInsight

## 第三栏：我准备怎么用

对应：
- ContentAsset
- DecisionRecord
- ProductHypothesis
- Action

这样把：

> 知识 → 灵感 → 行动

连起来。

# 十五、资产关系图

不要把资产都当孤岛。

尽量建立关系：
- supports：支持
- contradicts：冲突
- refines：修正
- example_of：案例
- derived_from：来源
- applies_to：适用
- inspired_by：启发
- tested_by：验证
- replaced_by：替代

未来检索时才能形成网络，而不是文件堆。

# 十七、批量材料处理

如果用户一次上传大量材料，不要一篇一篇机械总结。

先：
1. 按来源 / 场景 / 时间分组
2. 找重复主题
3. 找高密度判断
4. 找反复出现的用户问题
5. 找冲突
6. 找可升级资产

然后再决定哪些值得生成独立资产。

# 十八、资产去重

新输入和旧资产相似时：

## 完全重复
只增加：
- 新证据
- evidence_count
- last_verified_at

## 有新边界
更新旧资产版本。

## 新场景成立
增加场景证据。

## 实质不同
新建资产，并建立关系。

# 二十四、技术实现建议

如果未来接入真实数据库，建议逻辑上分三层。

## Raw Layer

保存：
- 原文件
- 原始对话
- 原始链接
- 原始转录

## Asset Layer

保存结构化资产。

## Model Layer

保存：
- 稳定规则
- 方法论
- IP 思维模型
- 表达档案

不要直接把所有原始材料塞进模型层。

---

# 二十五、隐私与权限

涉及客户信息、私聊、商业机密、个人隐私时，默认：

> private

对外内容使用前：
- 脱敏
- 改名
- 去身份信息
- 确认是否可公开

一个资产可被内部 AI 调用，不代表可以公开发布。

---

# 二十六、禁忌事项

严禁：

1. 把总结当资产化。
2. 什么都存。
3. 不保留原始来源。
4. AI第一次提炼就升级稳定规则。
5. 新结论覆盖旧结论、不留版本。
6. 冲突时直接删旧资产。
7. 把一次情绪当稳定价值观。
8. 把一次表达当稳定表达规律。
9. 把用户隐私直接变成公开案例。
10. 不区分事实、判断、推测。
11. 把外部作者的观点直接当 IP 自己的观点。
12. 看到好观点就自动写入“本人认知”。
13. 不标记来源场景。
14. 直播口语污染正式文档表达规则。
15. 咨询判断脱离具体场景后无限泛化。
16. 大量重复资产不去重。
17. 只存内容，不存为什么重要。
18. 只存结果，不存证据。
19. 只存成功，不存失败和反例。

# 二十八、最终目标

这个 Skill 最终不是让用户拥有更多收藏、更多笔记、更多文档。

而是让每一次输入都经过一次判断：

> 这是什么？
> 对我有什么用？
> 它改变了什么？
> 值不值得留下？
> 以后什么时候调用？

当输入不再只是“看过”，而开始进入知识、判断、案例、用户、决策、内容、产品这些结构里，IP 才真正开始形成自己的知识资产。

**世界进入你，不应该只是被你看见，而应该让你的系统发生变化。**
